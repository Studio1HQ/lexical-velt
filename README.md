# WriteFlow Lexical Editor with Velt

### A Lexical rich text editor with Velt inline comments, cursors and presence

WriteFlow is a Next.js writing app built on Lexical. Velt adds inline comments through the Lexical plugin, live cursors, presence and JWT-based authentication from an API route.

## Overview

WriteFlow is a collaborative rich text writing app built with Lexical, Next.js and [Velt](https://velt.dev). Users highlight text and comment on it through the Velt Lexical plugin, see each other's cursors and presence, and sign in to Velt with a JWT generated by a server route. A live demo is at [writeflowl-exical-velt.vercel.app](https://writeflowl-exical-velt.vercel.app).

It is a reference for adding Velt comments to a Lexical editor, including a custom bubble menu and toolbar.

## Features

- **Lexical editor**: Extensible editor framework with rich text, lists, links, code, tables, markdown shortcuts and marks.
- **Floating bubble menu**: Bold, italic, link and comment tools appear when text is selected.
- **Toolbar**: Headings, lists, quotes and other formatting.
- **Inline comments**: `@veltdev/lexical-velt-comments` maps Lexical nodes to Velt comment annotations, rendered with a `CommentNode` and `renderComments`.
- **Live cursors and presence**: `VeltCursor` and `VeltPresence`, with the presence avatars in the navbar.
- **Comment counter**: The navbar shows the number of active threads.
- **User switching**: Toggle between User 1 and User 2 in the navbar to test collaboration.
- **JWT authentication**: A server route issues signed Velt tokens.
- **Themes and responsive layout**: Dark and light mode, and a mobile sheet menu.
- **Default content**: The editor starts with an article template.

## Getting started

### Prerequisites

- Node.js 18 or newer
- A Velt API key and auth token from the [Velt console](https://console.velt.dev)

### Installation

```bash
git clone https://github.com/Studio1HQ/lexical-velt.git
cd lexical-velt
npm install
```

### Environment variables

Create a `.env.local` file in the project root.

| Variable | Description |
| --- | --- |
| `NEXT_PUBLIC_VELT_API_KEY` | Public Velt API key used to initialise `VeltProvider` in the browser. |
| `VELT_AUTH_TOKEN` | Velt auth token used on the server to request user JWTs. Keep it secret. |

Both come from the [Velt console](https://console.velt.dev).

### Run

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Other scripts: `npm run build`, `npm run start`, `npm run lint`.

To try it: highlight text and click the comment icon in the floating menu. Open the app in two windows, set one to User 1 and the other to User 2 with the navbar dropdown, and watch the cursor move in the other window.

## How it works

The editor registers `CommentNode` from `@veltdev/lexical-velt-comments` and renders comments from the Velt annotations:

```tsx
import { CommentNode, renderComments, addComment } from "@veltdev/lexical-velt-comments";

const editorConfig = { nodes: [..., CommentNode] };

useEffect(() => {
  renderComments({ editor, commentAnnotations: annotations });
}, [annotations]);
```

Authentication uses a server-side token flow:

1. The client calls `/api/velt/token` with user info.
2. The route calls the Velt API with `VELT_AUTH_TOKEN`.
3. Velt returns a signed JWT for the client session.

```text
├── app/
│   ├── api/velt/token/route.ts   # JWT token endpoint
│   ├── userAuth/                 # Demo user context and switching
│   ├── layout.tsx
│   └── page.tsx                  # VeltProvider and editor
└── components/
    ├── editor/                   # Lexical editor and plugins (toolbar, bubble menu, Velt comments)
    ├── velt/                     # VeltCollaboration, VeltInitializeDoc, VeltInitializeUser, VeltTools, UI customisation
    ├── navbar.tsx                # Presence, comments counter, user switch
    └── theme-provider.tsx, theme-toggle.tsx
```
